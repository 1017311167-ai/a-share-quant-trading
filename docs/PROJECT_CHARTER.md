# 股票实盘交易系统项目章程

## 1. 项目定位

本项目定位为面向中国 A 股现金股票的量化交易系统。目标链路为：

`研究 -> 回测 -> QMT 模拟盘 -> 小资金试运行 -> 正式实盘`

当前实现主要处于回测与交易接口原型阶段。QMT 适配器已经具备连接、资金、
持仓、限价下单、撤单和实时行情订阅能力，但尚未形成可接真实资金的完整交易闭环。

项目名称和功能边界以本文档为准。README、界面说明和后续设计不得与本文档冲突。

## 2. 项目目标

系统必须优先满足以下目标：

1. 策略研究可复现，能够追溯代码版本、数据版本、参数和交易成本假设。
2. 回测、模拟盘和实盘使用同一套策略信号与交易规则，避免研究交易偏差。
3. 所有订单都经过交易前风控，风控规则不能被策略模块绕过。
4. 信号、订单、成交、持仓、资金和风控事件全部可审计。
5. 程序重启、网络中断、行情中断和券商异常后可恢复或安全停机。
6. 模拟盘、小资金试运行和正式实盘之间必须经过明确的验收门禁。

系统不以承诺收益为目标。系统质量优先于新增策略数量或界面数量。

## 3. 支持范围

### 3.1 首版支持

- 中国市场 A 股现金股票。
- 沪深主板、创业板和科创板。
- 日线及分钟线研究、回测和低换手自动交易。
- QMT 模拟账户和经审批的 QMT 实盘账户。
- 限价买入、限价卖出、撤单、成交查询、持仓查询和资金查询。

### 3.2 明确暂不支持

- 期货。
- 期权。
- 融资融券。
- 卖空、杠杆、场外衍生品和自动组合保证金。
- 北交所股票。
- 可转债、ETF 和 LOF。
- 市价单、条件单和未经单独验证的高级订单算法。

如需扩展上述能力，必须建立单独的研究、回测、模拟盘和实盘准入方案，
不能通过修改参数直接启用。

## 4. 核心原则

1. 风控优先：任何下单动作必须先通过资金、持仓、价格、仓位、频率和账户状态检查。
2. 失败关闭：行情、连接、对账或持久化异常时，默认停止开仓，而不是继续猜测状态。
3. 幂等交易：同一策略、标的、方向和交易周期只能生成一次有效订单意图。
4. 对账优先：本地状态与券商状态不一致时立即停止新增风险，并以券商数据为准。
5. 人工急停：系统必须提供停止开仓、只减仓和全部撤单能力。
6. 分阶段放量：没有通过前一个阶段的验收，不得进入下一阶段。
7. 参数冻结：正式实盘不得在交易时段自动调整风控阈值或策略参数。

## 5. 阶段总览

| 阶段 | 账户 | 核心目标 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 模拟盘 | QMT 模拟账户 | 验证完整交易闭环 | 连续 20 个交易日满足模拟盘验收 |
| 小资金试运行 | 实盘账户、受限资金 | 验证真实成交与风控 | 连续 20 个交易日满足小资金验收 |
| 正式实盘 | 实盘账户、审批额度 | 稳定、可控、可审计运行 | 按季度评审额度，不设置自动扩张 |

详细定义见 `docs/TRADING_STAGES.md`。

## 6. 项目完成定义

股票实盘系统只有在满足以下条件后才可称为“可用于实盘”：

- 模拟盘完成完整订单生命周期和账户对账。
- 小资金试运行达到规定时长和最低订单样本。
- 风控、断电、断网、重启和重复信号演练全部通过。
- 每笔订单都可以追溯到信号、规则和配置版本。
- 系统可以在异常时自动停止开仓，并支持人工快速接管。
- 运行手册、回滚方案和告警流程已经验证。

## 7. 变更治理

- 策略进入实盘白名单必须经过独立评审。
- 风控阈值变更必须记录原因、审批人、生效时间和回滚值。
- 订单接口、风控、资金计算和对账逻辑的修改必须有单元测试和集成测试。
- 任何涉及真实资金的发布必须先经过模拟盘回放和小资金灰度。
